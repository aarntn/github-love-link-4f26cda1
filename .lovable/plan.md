
# Klinika — Clinician Copilot Dashboard

A calm, professional 3-tab dashboard for healthcare workers to monitor AI-triaged patient cases in KL. Reads/updates a single `triage_cases` table in Lovable Cloud (Supabase), with realtime subscriptions and seeded sample data.

## 1. Backend (Lovable Cloud)

Enable Lovable Cloud, then create a migration with:

**Table: `triage_cases`**
- `id` uuid PK default `gen_random_uuid()`
- `created_at` timestamptz default `now()`
- `channel` text — `web` | `whatsapp`
- `mode` text — `citizen` | `anonymous`
- `language` text
- `chief_complaint` text
- `flow` text — `dengue` | `tb` | `ncd` | `general`
- `urgency` text — `emergency` | `urgent` | `routine`
- `red_flag` boolean default false
- `postcode` text nullable
- `is_dengue_hotspot` boolean nullable
- `recommended_clinic` text
- `triage_summary` text
- `status` text default `new` — `new` | `reviewed` | `escalated`

**RLS:** Enable RLS. Since this is an internal clinician tool with no auth requested, allow public read + update (no insert/delete from client — backend handles inserts via service role). Policies:
- SELECT: `true` (anyone can read)
- UPDATE: `true` but restricted to only changing `status` column (or just allow update on all — simpler)

**Realtime:** Enable on `triage_cases` (`alter publication supabase_realtime add table triage_cases` + `replica identity full`).

**Seed:** Insert 12 rows via the migration covering:
- 2 emergency red-flag (chest pain English/web, stroke symptoms Malay/whatsapp)
- 4 dengue (2 in hotspot postcodes 52100/50480, mix of urgent/routine, citizen/anonymous, EN/MS/Tamil)
- 2 TB anonymous mode (whatsapp, Bangla + Tamil)
- 3 NCD/medication (routine, citizen, mix of channels)
- 1 general query
Statuses mixed: ~6 new, 3 reviewed, 3 escalated. Created_at staggered across last 6 hours.

## 4. Behavior details

**Live Cases tab**
- Initial load: `select * order by created_at desc`.
- Subscribe to realtime INSERT/UPDATE/DELETE → merge into local state.
- Sort: `red_flag=true` first, then `created_at desc`.
- Filters in local state, applied client-side.
- Card: channel icon (Globe/MessageCircle from lucide), language pill, flow tag (color per flow), urgency badge (coral/amber/teal-muted), time-ago, clinic line. Red left border (4px coral) when `red_flag`.
- Click → open `Sheet` (right side) with all fields including summary, postcode, hotspot, mode, status.

**Clinician View tab**
- Filter to `status in ('new','escalated')`.
- Sort: emergency → urgent → routine, then created_at desc.
- Counter chip "X cases awaiting review".
- Buttons call `update triage_cases set status=... where id=...`; optimistic UI + framer-motion `AnimatePresence` exit.

**Impact tab**
- One query, derive all stats client-side with `useMemo`.
- Stat cards: total, red flags caught (`red_flag=true`), dengue hotspot referrals (`flow='dengue' and is_dengue_hotspot=true`), anonymous-mode count.
- Recharts: bar (flow), donut/pie (channel), horizontal bar (language), table (group by recommended_clinic, count desc, top 5).
- Re-subscribe to realtime so charts update live too.

## 5. Tech notes

- Use TanStack Query for fetching + cache; realtime subscription invalidates `['triage_cases']`.
- Browser Supabase client (`@/integrations/supabase/client`) is sufficient — no server functions needed since reads/updates are public per RLS.
- framer-motion for card exit animation on action.
- recharts (already common in shadcn template) for charts; install if missing.
- Responsive: tabs stack nicely on mobile but layouts are desktop-first (multi-column grids at `lg:`).
- SEO `head()` on index route: title "Klinika — Clinician Copilot", description.

## 6. Out of scope (explicit)

- No auth / login (internal tool assumption).
- No creating new triage cases from UI.
- No editing case fields other than `status`.
